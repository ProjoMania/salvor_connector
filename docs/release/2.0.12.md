# Salvor Connector 2.0.12

> **Do not use 2.0.12. It is superseded by 2.0.13.** 2.0.12 trusted Cloudflare's `CF-Connecting-IP`
> header by default on every install, and after a successful pairing it showed the error "The pairing
> code must look like SLV-XXXX-XXXX." although the pairing had been saved. See `2.0.13.md`. The text
> below is kept as the record of what 2.0.12 changed, with two sentences corrected.

Fixes from a customer test on 2026-11-19.

## What changed
- **Behind Cloudflare:** when the address Odoo resolved for a request (the socket peer, or the
  right-most `X-Forwarded-For` entry with `proxy_mode`) is one of Cloudflare's published edge ranges,
  the allowlist checks `CF-Connecting-IP` instead. From any other address that header is ignored. (This
  note first said the header "cannot be forged by calling the origin directly". That was too strong: the
  trust was on for every install, and an address in Cloudflare's ranges does not show that a request came
  through your own Cloudflare zone. 2.0.13 makes it an option that is off by default.) The ranges are
  built in (`tools.CLOUDFLARE_RANGES`, fetched 2026-11-19). Before this, a Cloudflare-proxied Odoo with
  `proxy_mode` but no nginx `real_ip` config saw a Cloudflare edge address and refused Salvor with
  `403 ip_forbidden`.
- **`ip_forbidden` says what Odoo saw:** the 403 body now carries `remote_addr` (the address checked)
  and `cloudflare` (whether it is a Cloudflare edge). Only a caller holding the database's token gets
  that far; the allowlist itself is never returned.
- **Pairing errors are readable:** a refused pairing shows Salvor's own explanation (its `detail`), e.g.
  the https-only message, not just the HTTP status.
- **Pairing tests reachability:** right after pairing, the module asks Salvor to call
  `/salvor/v1/info` with the new token. If Salvor cannot get through (wrong address seen, TLS,
  firewall) the settings form says so at once (Connection test), instead of the first backup failing.
  The pairing itself is kept either way. A Salvor without the check answers 404: "Not tested".
  (In 2.0.12 a test that succeeded ended in a false error message; fixed in 2.0.13.)

## Upgrade
Go to 2.0.13, not to 2.0.12.
