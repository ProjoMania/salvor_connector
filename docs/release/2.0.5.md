# Salvor Connector 2.0.5

Follow-up to the 2.0.4 security release (advisory SC-2026-01, `SECURITY.md`). Upgrade from any earlier
version.

## What changed
- The removed drill routes (`drill/start`, `drill/upload`, `drill/restore`, `drill/status`, legacy
  `/salvor/v1/restore`) now check the token, source address and *enabled* flag before answering, like
  every other route: an anonymous caller gets the same 401/403, and every refusal is logged in the Pull
  Log. A caller that passes the checks gets **410 `drills_removed`**. The body is never read; any body
  over 1 KiB gets 413 from Odoo on every one of these routes.
- The *Allow restore drills* setting is removed (it could no longer be switched on). `info` still
  reports `drill_enabled: false` for older Salvor workers.
- Clean-up: stale comments, the "backup or restore" wording in 409 `busy`, an unused pattern.
- Leftover `salvor_drill_*` databases from 2.0.0/2.0.1 are still removed as in 2.0.4. Backups are
  unchanged.

## Upgrade
1. Pull your branch (`17.0`, `18.0`, `19.0` or `20.0`).
2. **Restart Odoo** (it keeps running the old Python code until restarted).
3. Upgrade the module: `-u salvor_connector`, or *Upgrade* in Apps.
4. Coming from 2.0.2, 2.0.3 or 2.0.4: the pairing is kept. Coming from 1.0.0, 2.0.0 or 2.0.1: pair
   again (Salvor refuses those versions): take a new pairing code in Salvor and click **Connect**.
