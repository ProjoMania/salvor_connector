# Salvor Connector 2.0.10

Adds **Odoo 16**, and closes a gap in the body-size limit on every branch.

## What changed
- **Chunked bodies (all branches):** the per-route body limit (64 KiB on working routes, 1 KiB on the
  removed drill routes) did not apply to a body sent without a Content-Length (`Transfer-Encoding:
  chunked`): werkzeug does not cap such a stream, so Odoo could read and parse a large form before the
  token check answered 401. An `ir.http._pre_dispatch` override on the `/salvor/` routes now answers 413
  for a chunked body, and for a declared Content-Length over the limit, before parsing and before the
  token check. Salvor always sends a Content-Length, so normal calls are unaffected. Regression test:
  `test_chunked_bodies_refused_before_auth`.
- New branch `16.0`, ported from 2.0.9 on 17.0. Differences from 17.0:
  - the settings form uses Odoo 16 `attrs` for its conditional parts;
  - Odoo 16 has no `max_content_length` route option, so an `ir.http._pre_dispatch` override applies
    the same per-route body limits (64 KiB on every working route, 1 KiB on the removed drill routes)
    before Odoo parses the body and before the token check, answering 413.
  The `16.0` branch previously held a 1.0.0-era module line; 2.0.10 replaces it.
- Requirements: Odoo 16, 17, 18, 19 or 20 on Linux. On 16, 17 and 18 the URL must lead to exactly one
  database.
- Store page: the repository address is printed as text next to "Details: SECURITY.md"
  (github.com/ProjoMania/salvor_connector), because the store shows links as plain text.
- `SECURITY.md` / `TAGS.md`: verify tags with `git verify-tag` and the key in `SECURITY.md`; GitHub
  shows tags up to 2.0.8 as *Verified*. `TAGS.md` has the 2.0.9 hashes and the 2.0.10 row.
- CI: the conflict-marker workflow can also be run by hand (`workflow_dispatch`).

## Upgrade
Recommended on 17.0 to 20.0 (the chunked-body fix); pull, restart Odoo, `-u salvor_connector`.
On Odoo 16, install from the
`16.0` branch. From anything older, follow `docs/release/2.0.6.md`.
