# Salvor Connector 2.0.6

Small hardening release on top of 2.0.5. Advisory SC-2026-01 (`SECURITY.md`) still applies to
older versions: upgrade from anything below 2.0.4.

## What changed
- `drill_enabled` returns as a non-stored, always-false compatibility field (not a setting). 2.0.5
  removed it, so when upgrading from 2.0.1 or older (1.0.0, 2.0.0, 2.0.1) the settings form still
  stored in the database crashed the web client after the Odoo restart and before
  `-u salvor_connector`. 2.0.6 renders that form; after `-u` the field is no longer shown.
- Every working route (`info`, `backup`, `backup/start`, `backup/status`, `backup/download`,
  `backup/cleanup`, `drop`) now refuses a request body over 64 KiB with 413 before Odoo parses or
  spools it, and before the token is checked. These routes only ever take a small JSON body; the drill
  stubs keep their 1 KiB limit.
- Vulnerability reporting: GitHub private vulnerability reporting is enabled (**Security → Report a
  vulnerability**), and reports can also go by email to **security@salvorcloud.com**. Named in
  `SECURITY.md`, the README advisory and the store page.

## Upgrade
Pull your branch, restart Odoo, upgrade the module (`-u salvor_connector`). From 2.0.2–2.0.5 the pairing
is kept; from 1.0.0, 2.0.0 or 2.0.1 pair again (see `docs/release/2.0.5.md`).

| Odoo | Module version |
|---|---|
| 17.0 | 17.0.2.0.6 |
| 18.0 | 18.0.2.0.6 |
| 19.0 | 19.0.2.0.6 |
| 20.0 | 20.0.2.0.6 |
