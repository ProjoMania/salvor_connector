# Salvor Connector 2.0.4

**Security release. Upgrade from any earlier version.** See advisory SC-2026-01 (`SECURITY.md`).

## What changed
- **Restore drills removed from the module.** The restore code (the detached restore runner, the psql
  meta-command guard, the neutralization tail, the drill claim/upload/restore/status logic, every
  `psql`/`pg_restore` invocation) is deleted. The only external program the module starts is `pg_dump`
  (backups, plus the Odoo zip format).
- `drill/start`, `drill/upload`, `drill/restore`, `drill/status` and the legacy `/salvor/v1/restore` stay as
  stubs that answer **410 `drills_removed`** without reading the request body (`drill/upload` bodies over
  1 KiB get 413 from Odoo).
- `info` no longer reports `upload_chunk_max`; `drill_enabled` is always `false`; capabilities are
  `backup_job`, `range_download`, `audit_log`, `drill_cleanup`.
- Leftover `salvor_drill_*` databases created by 2.0.0/2.0.1 are still removed, ownership-checked by
  name and PostgreSQL oid: warning and *Drop them now* on the settings form (administrators only), the
  hourly action (24 h; 6 h for unfinished ones), *Disconnect*, uninstall, and Salvor's `drop` call.
- Backups are unchanged.

## Upgrade
1. Pull your branch (`17.0`, `18.0`, `19.0` or `20.0`), or the tag `<series>-2.0.4` once it is created (tag to be created).
2. **Restart Odoo** (it keeps running the old Python code until restarted).
3. Upgrade the module: `-u salvor_connector`, or *Upgrade* in Apps.
4. Check the settings form still says "Connected to Salvor".

Upgrading from 2.0.2 or 2.0.3 keeps the pairing. From 1.0.0, 2.0.0 or 2.0.1 pair again: Salvor refuses
connectors below 2.0.2. Prefer the latest version (2.0.6) over 2.0.4.
