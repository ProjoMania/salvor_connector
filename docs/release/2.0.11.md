# Salvor Connector 2.0.11

Hardening release on top of 2.0.10. Upgrade on every branch (`16.0` to `20.0`).

## What changed
- **Odoo 16 uninstall fixed (16.0 only):** 2.0.10 on 16.0 declared `uninstall_hook(env)`, but Odoo 16
  calls `uninstall_hook(cr, registry)`, so uninstalling the module failed with a `TypeError`. The hook
  now has the Odoo 16 signature. A test checks the hook against the call each Odoo version's module
  loader makes.
- **Chunked bodies, with a Content-Length too:** a request that carries `Transfer-Encoding: chunked`
  is refused with 413 on every `/salvor/` route whatever its Content-Length says, before the body is
  parsed and before the token check. (With the werkzeug versions Odoo 16 to 20 ship, 2.0.10 already
  answered 413 for such a request; 2.0.11 no longer depends on that.)
- **No-database path:** the `/salvor/` routes are now `auth="public"`. Odoo serves only `auth="none"`
  routes on its no-database path, so loading the module server-wide (`--load=...,salvor_connector`) no
  longer exposes the routes, and their body checks, without a selected database. With a database the
  routes behave as before (the token check is the module's own).
- **Tests:** the chunked-body test covers all 12 `/salvor/` POST routes, with and without a token and
  with and without a Content-Length, and counts a dropped connection as a failure. New tests check that
  no `/salvor/` route is on the no-database routing map and the uninstall-hook signature.
- `SECURITY.md` and the README name the second advisory, GHSA-28rv-398c-r5xx (chunked request bodies).
  `TAGS.md`: 2.0.10 hashes and the 2.0.11 row.

Pull your branch, **restart Odoo**, `-u salvor_connector`. The pairing is kept.

## Multi-database servers (read before upgrading)

Salvor routes are no longer served on Odoo's "no database selected" path. On a server hosting several databases:
- **Odoo 19 and 20:** Salvor sends `X-Odoo-Database`; nothing to do.
- **Odoo 16, 17 and 18:** set a per-host `dbfilter` (for example `dbfilter = ^%d$`) so each hostname selects one database. A setup that relied on loading the module server-wide (`--load=…,salvor_connector`) without a `dbfilter` stops working with 2.0.11. That setup was never documented.

A `dbfilter` selects the database Odoo routes to; access is still decided by the per-database Salvor token.
